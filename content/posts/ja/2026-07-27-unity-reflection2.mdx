### Raycastを使った敵戦車の行動パターン

{/* @layout-id t-06d202fc-9a58-4493-a4a7-d7912e7cc022 */}

敵戦車の移動や攻撃の自動化には、Raycastを使用しました。

</ArticleBlock>

<ArticleBlock id="b-9cce718f-067a-4166-9b2d-66def34d1d15">

{/* @layout-id t-f256838f-8872-4505-aec4-9d0e72d205fd */}

仕組みとしては、1作品目の接地判定で使った `Physics2D.BoxCast` と似ています。敵戦車の前方にRayを飛ばし、壁を検知したら進行方向を変えるというものです。

</ArticleBlock>

<ArticleBlock id="b-2ac20d08-a58f-40c9-ab08-5eb977ce33a5">

{/* @layout-id t-3656f9e5-02b6-4090-9695-0216e7d9bc85 */}

簡略化すると、次のような処理です。

</ArticleBlock>

<ArticleBlock id="b-16b2b63a-c54f-4192-90ca-b074d45b148e">

{/* @layout-id t-eb1eff30-969a-4b5c-ac18-f5cc32ca6052 */}

```csharp
RaycastHit2D hit = Physics2D.Raycast(
    frontSensor.position,
    transform.right,
    sensorLength
);

if (hit.collider != null && hit.collider.CompareTag("Wall"))
{
    // 壁を検知したら回頭する
    transform.Rotate(
        0,
        0,
        avoidTurnSpeed * Time.deltaTime
    );
}
else
{
    // 前方に壁がなければ前進する
    transform.Translate(
        Vector3.right * moveSpeed * Time.deltaTime,
        Space.Self
    );
}
```

</ArticleBlock>

<ArticleBlock id="b-e9f5d96d-db8e-4e9e-a039-fc6a26ce2b53">

<Photo assetId="asset-b763ad91-17a3-446e-9961-b4b9a5ad3054" src="/images/Articles/Unity/ArmorBreakers/ArmorBreakersDev.png" alt="戦車ゲーム開発画面（Raycast）" fit="contain" kind="screenshot" />

</ArticleBlock>

<ArticleBlock id="b-a65fc22b-196b-47d8-bdd0-8670316347b4">

{/* @layout-id t-08aa0421-a924-4f37-bc6f-16c1613f9e95 */}

上の画像には、敵戦車を中心に2つの円があります。

</ArticleBlock>

<ArticleBlock id="b-3019a846-7674-4d0a-b1bd-50003bb868b5">

{/* @layout-id t-3e3b553f-f86e-4d0b-aef8-0e4cacaf0b6c */}

内側の円が索敵範囲です。プレイヤーがこの範囲に入ると、敵戦車は巡回モードから追跡モードへ移行します。

</ArticleBlock>

<ArticleBlock id="b-a6d42a20-3c7c-4bfc-8d6a-428b9b2b8af7">

{/* @layout-id t-bbf40ab8-cfb4-4930-914f-8d54c26b8084 */}

外側の円は、プレイヤーを見失ったと判定するための範囲です。プレイヤーが外側の円から出た時点で、追跡モードから巡回モードへ戻ります。

</ArticleBlock>

<ArticleBlock id="b-529cee73-cbe3-4f92-ac10-ab9959a997f9">

{/* @layout-id t-ba2124a1-6f7a-4b77-905b-6ada50139a7c */}

索敵を開始する範囲と見失う範囲を分けることで、境界付近で巡回と追跡が何度も切り替わるのを防いでいます。

</ArticleBlock>

<ArticleBlock id="b-5d0eaef8-f282-45c2-845a-3aed028a5da8">

{/* @layout-id t-06b9d63d-1ad3-4a90-a419-16ae2adcd37a */}

戦車の前方から伸びている3本のRayは、障害物を避けるためのものです。ほかにも砲身からRayを飛ばし、その先にプレイヤーがいる場合に弾を発射する処理にも使用しました。

</ArticleBlock>

<ArticleBlock id="b-e4be0ecf-bb57-4b15-84f0-b677a585b8c0">

{/* @layout-id t-8414c327-3054-471e-8748-74771edb4a19 */}

</ArticleBlock>

缶のどこをクリックしても同じ方向へ飛ぶのではなく、クリックした位置によって、缶が飛ぶ方向と回転する向きが変わるようにしました。

</ArticleBlock>

<ArticleBlock id="b-f26b18a3-1833-4ec4-9cad-3f7c48a79897">

{/* @layout-id t-ab4a4df8-db75-4e89-9480-0e2c13cfb3d5 */}

```csharp
void OnMouseDown()
{
    Vector2 clickPos =
        Camera.main.ScreenToWorldPoint(Input.mousePosition);

    // 缶の中心とクリックした位置の差
    float xOffset = transform.position.x - clickPos.x;

    // クリックした位置と反対方向へ飛ばす
    Vector2 direction = new Vector2(
        xOffset * sideForceMultiplier,
        upForce
    );

    rb2D.AddForce(direction, ForceMode2D.Impulse);

    // クリック位置に応じて回転を加える
    rb2D.AddTorque(
        xOffset * torqueMultiplier,
        ForceMode2D.Impulse
    );
}
```

</ArticleBlock>

<ArticleBlock id="b-e9545c7e-5724-4986-9e20-4c0c28c5a821">

{/* @layout-id t-235bc7a9-b90d-4933-8df5-cd4dad2a78f0 */}

缶の中心より右側をクリックすると、缶は左方向へ飛びます。反対に、左側をクリックすると右方向へ飛びます。

</ArticleBlock>

<ArticleBlock id="b-3bae2084-772c-43ad-9e0b-8df2c6045429">

{/* @layout-id t-8e97c6bb-d3d5-40e0-aeb4-5c4d52f165db */}

回転方向もクリックした位置によって変わります。

</ArticleBlock>

<ArticleBlock id="b-1b126ac7-60fd-4822-b9fd-9ebd9f9e9050">

{/* @layout-id t-bbc088db-a8f8-4e6c-8377-601a913af9e4 */}

- 缶の右側をクリック：`xOffset` が負になり、時計回りに回転する
- 缶の左側をクリック：`xOffset` が正になり、反時計回りに回転する

</ArticleBlock>

<ArticleBlock id="b-e97336ce-581d-4319-b10d-bead94d103c7">

{/* @layout-id t-c76706a6-c4fe-46cd-8b9a-29341d15f6a4 */}

クリックする位置が少しずれるだけで缶の軌道が変わるため、狙った場所へ飛ばすには微妙な調整が必要になります。

</ArticleBlock>

<ArticleBlock id="b-665e5f0d-2fe4-44cb-a09c-255fbcdc055d">

{/* @layout-id t-c93968b2-83cc-4ee5-8b14-404b0ad73061 */}

シンプルなクリック操作でも、位置や力の加え方を変えることで、ゲームらしい操作感を作れることを学びました。

</ArticleBlock>

## 7作品を振り返って

{/* @layout-id t-9987ac56-0354-4f74-a955-16f69ca639bf */}

これまでに作ったゲームは、全部で7本です。

</ArticleBlock>

<ArticleBlock id="b-2059c12c-4f3e-4e4d-9bf8-f329cc2e8b09">

{/* @layout-id t-415b35ec-5d57-45bb-ab3c-6c87bd50825c */}

「たった7本」とも言えますが、その7本を作る中で多くの失敗を経験し、自分のアウトプットと向き合う時間を重ねてきました。

</ArticleBlock>

<ArticleBlock id="b-aa923fc6-a1ee-47eb-a140-31314f38fef5">

{/* @layout-id t-6ed8bc70-492b-488d-96df-33073540d1ca */}

最初は、ハンズオン動画を見ながらUnityの操作や基本的な実装を覚えるところから始まりました。

</ArticleBlock>

<ArticleBlock id="b-9061dc22-f381-4f1a-98ec-c0eb5bf8c6dd">

{/* @layout-id t-8888041b-ac3a-4de1-b375-0c30f74472fd */}

そこから、AIを使ったアセット制作、ルールベースAI、Raycastを使った敵の行動、クリック位置によって変化する操作感、ゲームバランスの調整など、少しずつ自分で考えて作る範囲が広がっていきました。

</ArticleBlock>

<ArticleBlock id="b-1fb8f55b-11a7-4bad-9f01-fe435f63b6b1">

{/* @layout-id t-feb96ea3-99f0-4dbc-a989-3acc7691345a */}

一方で、作品を重ねるたびに、実装できることと面白いゲームを作ることは別なのだと感じるようになりました。

</ArticleBlock>

<ArticleBlock id="b-9086e3e3-1da9-4466-9f9d-e0b4a7bd0ad6">

{/* @layout-id t-86b5c137-7dbf-4909-a16a-8b68660a0be2 */}

特に大きかった学びは、次の3つです。

</ArticleBlock>

<ArticleBlock id="b-c411d315-08e8-48ad-884e-6a51546b075b">

{/* @layout-id t-0274ec0c-88d0-46bc-934e-7c5c2cd5dfae */}

1. 作り始める前に、ゲームの核と完成範囲を決める
2. 自分以外の人に遊んでもらい、客観的な意見を受け取る
3. 機能を増やす前に、それが本当に面白さにつながるのかを考える

</ArticleBlock>

<ArticleBlock id="b-f3e5a57f-2a90-4ba3-961c-cd090b3f2b17">

</ArticleBlock>
