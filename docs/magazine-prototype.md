## 参考画像との比較

最新添付の3枚はいずれも完成イメージ。暗いホーム、明るいホーム、記事の見開きの順で閲覧した。既存の単色ワイヤーフレームが修正対象であり、添付画像を現在の実装として扱っていない。

| 項目 | 参考から観察した内容 | 実装 |
| --- | --- | --- |
| ホーム | 等幅3列、縦長表紙、タイトル・短文・小さな日付 | 6記事。4:5の表紙、同じ行の上下端と次の行の開始位置が一致 |
| 表紙 | 写真が大きく、題字は写真の空いた場所に配置 | タイの写真、該当Unity作品の画面、機械学習記事の図版。写真なしの記事は文字主体の表紙 |

| 記事左 | 全面写真に題名・導入文 | 実際のバンコク夜景。短題「初めての、タイ。」と副題。空の部分に文字を配置 |
| 記事右 | 小見出し、写真＋横の短文、下の2段、小さな補助写真 | 主写真64%、横の文章32%、間隔4%。実際の飛行機の夕日とホテルのランタンを使用 |
| 見開き | 同じ大きさの左右ページ、中央の細い溝 | 1536×1024で約1392×870px。ヘッダーからページ送りまで同時表示 |

1122px幅のホームでは表紙が約330×412px、列間隔28px。1段目の上端154px、2段目752px、全体約1466px。明るい参考の表紙幅・列間隔はそれぞれ約330px・29px、2段目は約719px、画像全体1402px。これら参考の数値は画像からの概測。実装は説明文の可読性を優先し、縦方向に約64px長い。

旅行写真の青い夜景やゲーム画面の色はそのまま使用している。全記事が落ち着いた生活写真の参考とは色と写真面積が異なる。ゲームと図版は内容を切らないため、薄い地色の内側に全体を収めた。架空の記事・日付・SNS、制作説明、ファイル名は読者画面へ転記していない。

## 執筆方法

### ホームの表紙

`title`・`description`・`image`は正式情報として保持する。次の任意項目を追加する。掲載の優先順位は`homeOrder`の小さい順、その後pinned、日付の降順。試作は先頭6件を掲載し、「すべての記事」から既存の一覧へ移動する。

```yaml
displayTitle: "初めての、タイ。"
cardSummary: "ホテル選びの失敗も、長い移動も。初めてのタイをひとりで巡った記録。"
homeOrder: 1
cover:
  mode: composed
  template: photo
  title: "初めての、\nタイ。"
  subtitle: "大学1年、7泊9日のひとり旅。"
  image: "/images/Articles/Thai/Thai_night.JPG"
  focal: "62% 50%"
  position: top-left
  tone: light
  overlay: local
```

- `template`は`photo`（全面写真）、`inset`（ゲーム・図版の全体を表示）、`type`（文字主体）。`palette`は`sage`または`sand`を使用中。
- `position`は`top-left`・`top-right`・`bottom-left`。`tone`は`light`・`dark`。`focal`はCSSのobject-positionと同じ形式。
- `overlay: local`は局所的なグラデーション。全体を暗くするフィルターは使わない。写真の主題と文字がぶつかる場合はまず構図・文字位置を調整する。
- 完成画像は`mode: image`と`template: photo`、`image`を指定。HTMLの題字・カテゴリー・誌名を画像に重ねない。4:5枠内で画像全体を表示する。
- `displayTitle`と`cardSummary`は切り捨てない。試作の日本語6件は1122px幅で短題1行・概要2行。英語や狭い幅では必要な行数に伸びる。
- 画像がない場合も同じ4:5の外寸。`template: type`、短い題字、地色を指定する。

### 見開きの記事

タイ旅行記の実ファイルを執筆例にできる。記事専用TSX/CSSは不要。英語版は翻訳の分量に合わせてページ区切りを変えてよい。

```yaml
reader:
  mode: magazine
  title: "初めての、タイ。"
  subtitle: "大学1年、7泊9日のひとり旅。"
  image: "/images/Articles/Thai/Thai_night.JPG"
  focal: "62% 50%"
```

```mdx

<EditorialPhoto src="/images/Articles/Thai/AirJapan.jpg"
  alt="飛行機の窓から見えた夕日" focal="50% 61%">

</EditorialPhoto>

</EditorialColumn>
<EditorialColumn>

## 既存の見出しをそのまま使う

続きの本文。長い場合は段落の境界で次のMagazinePageへ分ける。

</MagazinePage>
```

`text`・`mixed`・`photo`は共通の紙面枠を使い、内部のMarkdown・写真パーツの組合せで構成する。通常の`ImageSlider`記法も、見開き内では全画像が読書順に並ぶギャラリーになる。写真ごとのaltが必要なときは`MagazineFigure`を使う。キャプションは`caption`で任意指定し、本文にない事実を書き足さない。

`MagazineFigure`は既定で画像全体を表示。切り抜いてよい場合だけ`fit="cover"`と`focal`を指定する。新しい画像の実寸をmanifestに登録すれば自然な比率を確保できる。未登録画像は4:3枠がフォールバックになる。表紙はmanifestに依存せず4:5固定。

既存本文をページ外に残さない。`reader.mode`を指定しない記事は通常の縦スクロール。コード・長い表・数式などを無理に2段へ押し込まず、通常記事を選べる。現在の技術・Unity記事はこの方式。

## 読書・画像・互換性

- 十分な画面（幅1280px以上かつ高さ860px以上）で見開きを試み、文字や写真が収まらなければ全文表示に切り替える。倍率で全体を縮小したり、文章を切り捨てたりしない。
- スマホは左→右→続きのページというDOM順。導入写真は最小360px、本文は写真の下。本文17px・行間1.95、右ページは1列。長題には自然な高さを確保する。
- PC本文18px、右ページ短文の段組み17px、写真横14px。本文サイズと行間を維持し、日本語21ページ・英語24ページに分けた。
- 目次・検索・既存の見出しURLから該当見開きを開く。ページ操作は`#page-{id}`を履歴へ追加する。戻る・進む・再読込はそのhashを復元する。ページIDは公開後に不用意に変更しない。
- `全文表示`とCtrl/Cmd+Fで全文を表示。OSのメニューからの検索開始は自動検知できないため、全文表示ボタンも常設。全本文はSSR時点で一つのHTMLとして出力し、ページ送りはDOMを削除せず表示を切り替える。
- 非表示ページはフォーカス・読み上げの対象から外す。前後ボタン・現在位置・最後の無効状態を明示し、ボタンにフォーカスがあるとき左右キーで送れる。めくりアニメーションは使わない。
- 画像領域の寸法を先に確保。開いた見開きとスクロールで近づいた画像を取得する。未表示の高解像度写真を一括でNext Imageへ渡さない。JavaScriptなしでは通常本文とnoscript画像が読める構造。
- 正式タイトル、description、公開日・更新日、URL、canonical・hreflang・JSON-LD、原文と既存画像参照、見出しIDを保持。いいねは同じslug、コメントは同じpathname。検索、翻訳、共有、カテゴリ・タグ、既存ページの導線を維持。
- 開発時には`data-overflow`属性に超過したページの寸法を記録する。自動フォールバックしたらそのページを確認し、段落を移す・ページを追加する・写真サイズを変える。読者画面に制作説明は表示しない。

## 検証

| 画面・操作 | 結果 |
| --- | --- |
| PC 1536×1024 | 見開き870px高。日本語21ページ・英語24ページを最後まで操作。初期見開きはヘッダー・操作まで画面内 |
| ホーム 1122px幅 | 3列×2段、表紙上下端一致、6画像枠中5件に実素材。全短題1行、全概要2行 |
| タブレット 834×1112 | ホーム2列。ページ全体の横スクロールなし |
| スマホ 390×844 | ホーム1列、記事は全文の縦スクロール。導入写真360px、本文開始は上端から約482px（内側余白を含む） |
| 狭幅 320×740 | 旅行記の本文・紙面に横のはみ出しなし |
| PC 1366×768 | 高さ不足で全文表示。全21ページを保持 |
| 履歴・操作 | 前後・最終ページ・戻る・進む・再読込・キーボード左右操作・Cmd+Fを確認 |
| 検索 | 「一眼レフ」で元の末尾本文を検索し、その見出しのある最終見開きを表示 |
| 長い技術記事 | scikit-learn記事の本文末尾・コード7件・表を確認。390px幅でページは横に伸びず、コードと表の内側だけがスクロール |

自動検証：既存分を含む9スイート・59テストが成功。追加テストはページ送り、履歴hash、短い画面、全文検索、はみ出し時の本文保持。ESLint、型チェック、本番ビルドを確認。13本の追跡記事すべてで元のメタデータを比較し、タイ旅行記の日英はMDXをHTMLへ変換して原文・元の画像参照・全見出しIDが一致することも確認した。

実機タッチ操作、OSの文字のみ200%拡大、JavaScript無効ブラウザ、実ネットワークでのCore Web Vitals、Neonへの保存、Giscusへの投稿は未検証。ブラウザの拡大ショートカットではこの確認環境の倍率が変わらなかったため、拡大確認済みとは扱わない。レイアウトの縮小幅・高さ不足と、はみ出し時の本文保持は上記の条件で検証している。
