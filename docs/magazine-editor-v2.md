## 保存する情報

- 記事：既存のtitle/date/category等に加え、`reader.schemaVersion: 2` と `reader.articleId`。
- 意味のまとまり：MDXの `<ArticleBlock id="journey-04">`。ページを移してもIDを保持。
- 本文要素：直前の非表示コメント `{/* @layout-id t-UUID */}`。本文変更でIDを再計算しない。段落・見出し・表・コード・独自コンポーネントを参照する。
- 画像：MDXの `<Photo assetId="asset-UUID" src="..." alt="..." caption="..." credit="..." kind="photo" />`。srcと寸法manifestは素材、表示比率・焦点は掲載箇所の設定。同じ写真を再利用するときは同じassetId。
- 配置：`reader.pages[].blocks`、template/layout、composition、photos。配置には本文を保存しない。新しい写真位置は`anchorId`で本文要素を参照し、配列番号を永続化しない。
- `sourceId` / `replacementId`は画像の安定参照。`source` / `replacement`のパスは互換用にも保持し、素材IDから解決する。

例（IDは説明用。実際には移行処理がUUIDを発行）：

```mdx
---
title: 正式な記事タイトル
reader:
  schemaVersion: 2
  articleId: article-123e4567-e89b-42d3-a456-426614174000
  mode: magazine
  pages:
    - id: departure
      template: feature
      layout: portrait
      blocks: [departure]
---

<ArticleBlock id="departure">

{/* @layout-id t-123e4567-e89b-42d3-a456-426614174001 */}

## 出発の日

{/* @layout-id t-123e4567-e89b-42d3-a456-426614174002 */}

ここに本文を書く。コメントはこの要素と一緒に残す。

<Photo assetId="asset-123e4567-e89b-42d3-a456-426614174003"
  src="/images/Articles/Thai/AirJapan.jpg"
  alt="飛行機の窓から見えた夕日" kind="photo" />

</ArticleBlock>
```

上の例は1ページだけでも成立する。導入・終幕や空白ページを自動追加しない。既存のopening・直後のeditorial・spotlightがある場合は、その本文割り当てを保護する。

## 型と操作

登録場所は `lib/layout-registry.ts`。ID、表示名、用途、候補理由、スロット、画像数・向き、PC/モバイル方針、代替型、はみ出し時の対応をまとめた。

| 型 | 選定の基本 |
| --- | --- |
| opening | 既存の全面写真の導入。文字色、位置、局所グラデーション、焦点 |
| portrait | 縦写真1枚。写真と隣接した本文 |
| landscape | 横写真1枚。写真の下へ本文 |
| pair | 関連する写真2枚 |
| text | 本文中心・写真なし。写真があれば補助として扱う |
| data | 表またはコードを含む内容 |
| mosaic | 既存の3枚以上の写真ページとの互換用 |

候補は画像数・向き・表やコードの有無から絞る。本文の自動書き換えや、閲覧時の自動再配置は行わない。本文量・実寸・余白は助言と実測で確認する。

通常の設定欄では、元比率 / 4:5 / 3:2 / 1:1、主役 / 補助、左 / 右 / 本文の上下、本文中の挿入位置、焦点を選ぶ。元画像と切り取り枠も表示できる。段落は全幅 / 75% / 60%、左 / 中央 / 右、標準 / 小 / 大の段落間隔。自由な座標やリサイズハンドルは提供しない。

密度はコンパクト / 標準 / ゆったり。新しいcomposition本文の基準は16px、行間1.85。見出しは標準22px、19px相当の小見出し。配色はpaper / sand / rust / sage / sky / ink。旧設定の数値は互換用に読み取るが、通常の操作では用意された選択肢から選ぶ。

## 編集方法

1. `.env.local` に `LOCAL_LAYOUT_EDITOR=1` を設定して開発サーバーを起動する。この作業環境では有効化済み。標準の `.env.example` は0。
2. ArticleBlock形式の記事を開き「誌面を直接編集」。ページ一覧・サムネイルからページを選ぶ。
3. テンプレート候補を確認して適用、または写真・段落を選択して設定を変更する。開くだけでは未保存変更を作らない。
4. PC / スマホ / 保存前と比較を切り替える。プレビューは同じ本文と描画コンポーネントを使う。
5. ⌘Zで取り消し、⌘Yまたは⌘⇧Zでやり直し（WindowsはCtrl）。文字入力中は入力欄本来のUndoを維持。1回のドラッグは1操作。
6. 「変更を保存」でMDXに反映。破棄する場合は「変更を取り消して閉じる」。項目単位の標準化も可能。
7. ページ割り当ては直接編集を閉じ、「誌面の配置を編集」→「現在の配置を読み込む」。境界のまとまりを隣へ移動、結合、指定した境界で分割する。
8. 「配置案を誌面でプレビュー」で未保存の案を実際の誌面へ表示する。元の表示との切替、割り当てUndo/Redo、差分確認、保存または破棄ができる。

改ページを固定したページは、固定を解除してから構成を変える。移動は隣接境界に限定し、本文の順序を維持する。奇数のページ数も許可し、末尾の空白ページを自動追加しない。

## 読書と検証

- 幅1200px以上は見開き、幅768〜1199pxは1ページ。高さ不足や本文のはみ出しでは、収まらない元ページだけを継続ページへ分割する。サイズ不足による全文スクロールへの自動切替は行わない。
- 本文を小さくする自動フィットや、紙面内スクロールによる隠蔽は使わない。フォント読込後と寸法変更時に計測する。
- モバイルは意味の順序で縦に読む。本文は18pxを基準とし、固定高さやPCの余白は解除。スマホプレビューにも同じブック幅のルールを適用する。
- 非表示ページはinert。目次、見出しアンカー、履歴、再読込位置、全文検索を維持する。
- 既存MDXコンポーネントは既存の登録を使用する。配置参照が本文編集で古くなった場合は、MDX本文を通常フローで表示する。構文自体の誤りや未登録コンポーネントは別途修正が必要。
- 保存では未知の設定・参照、割り当て漏れ・重複・順序逆転を拒否する。大きな余白や解像度・写真サイズは助言として扱う。

## 保存境界

読み書きAPIと未保存プレビューのServer Actionは、development + 明示フラグ + localhostでのみ有効。同一origin、許可されたlocale/slug、設定サイズ・スキーマ、本文の不変性を検証する。任意パス・symlinkは拒否。revision不一致は409で止め、外部編集を無断で上書きしない。一時ファイルへの書き込みが完了してからrenameする。保存と公開は独立。

IDの追加・移行コマンド：

```sh
pnpm exec ts-node --compiler-options '{"module":"CommonJS"}' scripts/migrate-layout-ids.ts
```

本文を手で編集した後に新しい要素のIDが必要なら、この明示的な操作を実行する。既存コメントを別の段落に付け替えない。移行前のバックアップは `.local-review/id-migration/` に残す。

## はみ出した誌面の扱い（スクロールへの自動切替を廃止）

PCの紙面に収まらない内容は、ブラウザの段組み分割で次の紙面へ送る。ページ送りは追加された紙面も含めて、左→右→次の見開きの順に進む。元の本文DOMは複製せず、MDXのページ設定も書き換えない。文字の縮小・本文の削除・紙面内のスクロールバーは使わない。

通常サイズで収まるページは保存した配置を維持する。収まらないページだけを読み順のある通常の文字組みに戻し、段落は行単位、コードは行単位、表は行を優先して分割する。写真は比率を保ち、紙面の高さに入る全体表示にする。長いページを手動で整える場合は、既存の配置編集で分割・結合・移動する。

継続位置は `#page-元ID--continuation-2` などのURLで復元する。見出しリンクは該当する継続紙面を開く。画面サイズ変更時は元ページを基準に再計算し、異なる画面では継続ページ数が変わる。明示的な「全文表示」とブラウザ内検索、スマートフォンの縦読みは維持する。

上の旧確認表にある「1440×500で全文」は変更前の記録。現在は同サイズでも見開きとページ送りを維持する。


今回の確認：1440×900で日本語Unity後編（25ページ）・タイ旅行記（16ページ）の元のページ数と全ページを確認。1440×500では長文・コード・表・旅行写真を含む記事の継続ページを最終ページまで確認。1024×600で1ページ送り、390×844で全ページの縦読みを確認した。700px高の画面で目次から見出しのある紙面へ移動でき、継続位置のURLから再読み込みも確認。自動検証は19 suites / 103 tests、型チェック・変更対象ESLintが成功。公開・デプロイはしていない。

## 編集画面と読者画面の寸法の一致

PC編集は見開きの片ページと同じ幅・高さを使い、編集用の本枠は必ず1列にする。後置した見開きの2列指定で編集ページを半分に縮めない。狭い本枠に適用するスマホ用の文字組み・写真配置は `data-reader-mode=flow` に限定し、PC編集の片ページには適用しない。

本文とリストは共通の `--mag-body-size: .875rem`（標準設定で14px）に統一。見出し・表・コード・キャプションは役割ごとのサイズを維持する。本文は編集／閲覧、PC／スマホで同じサイズを参照する。ブラウザの文字拡大は引き続き可能。

確認：1440×900で旅行記の導入・航空機写真・Day2本文、1024×900で費用ページについて編集／閲覧の紙面寸法と要素位置を比較。390×844でも本文サイズと横方向のはみ出しを確認。

## 要素単位の仕上げ

- 写真：右下ハンドルまたは数値で枠幅を調整。縦横比ロックを解除すると枠の高さも変更できる。幅は0.1%、比率は0.01単位で指定できる。
- 切り取り：全体表示／切り取り、1〜4倍ズーム、上下左右の焦点を組み合わせる。画像内のドラッグは焦点移動。元画像上に切り取り範囲を表示する。
- 段落・見出し：選択後、12・14・16・18・22・28・36・48pxから選ぶ。未指定ならテンプレートのサイズ。本文はMDXのまま、`textGroups[].fontSize`だけを保存する。
- テキスト枠：右下ドラッグで幅と追加の下余白（0〜500px）を調整。必要な本文高さは自動確保し、切り捨てない。数値入力も使える。スマホでは下余白を0に戻し、写真を全体表示する。
- 設定は既存の配置保存に統合。`bottomSpace`・`fontSize`・写真の`zoom`は省略可能で旧記事と互換。ドラッグは既存の履歴処理で1回のUndo／Redoになる。

確認：タイ記事で18px・下余白30px・幅90.24%・写真幅41.5%・ズーム1.25倍を保存し、再読み込み後の反映を確認。390px幅で追加下余白が0になり横はみ出しがないことを確認。確認用の記事変更は元へ戻した。

## 写真と文章を独立したブロックにする

写真枠は文章枠の子要素にせず、同じ本文領域の兄弟要素として描画する。写真の既定ドラッグ操作はブロック移動。最初のドラッグで現在位置を紙面内の自由配置に変換し、`position: free` と本文領域に対する百分率 `x` / `y` を保存する。「ドラッグ操作」で切り取り調整へ切り替えられる。従来の本文に沿う配置も選択できる。

`composition.allowOverlap` が有効な場合、写真はレイヤー1、文章はレイヤー2として重ねる。無効な場合は、写真・先行する文章枠を避けるよう本文領域を自動調整する。写真が紙面外に出る場合は許可設定にかかわらず警告する。スマホでは絶対配置を解除し、本文内の関連位置で縦へ流す。

確認：1440×900でドラッグ、重なり警告／許可、保存と再読み込み後の位置・サイズ一致を確認。390×844で通常配置と横はみ出しなしを確認。検証用の記事変更は復元した。105テスト通過。


## テキスト枠の自由移動と自動折り返し

文章枠の左上の✥をドラッグして紙面内で移動する。幅・下余白・個別文字サイズを保持し、`textGroups[].position/x/y` に配置だけを保存する。サイドパネルの「文章の配置方法」で本文に沿う配置へ戻せる。スマホでは座標を解除し、MDXの読む順序に戻す。

重なりを許可しない場合は、写真と先に配置された文章領域を、行ごとの回り込みで避ける。写真の下端を過ぎた行から利用できる幅が広がり、次の写真の高さでは再び狭くなる。本文は元のHTMLのまま保持し、不可視のCSS shape-outside境界だけを再計算する。中央の障害物の左右に同じ行を分断せず、一続きの読む領域を選ぶ。写真が左右へ交互に配置され、連続した読む領域を確保できない場合や、幅が狭すぎる場合は障害物の下へ送る。文章枠同士は元の読む順序を優先し、後の枠が先の枠を避ける。紙面に収まらない場合は保存前に警告し、切り捨てない。重なり許可時はこの補正を解除する。

確認：PCで文章のドラッグ、写真・他文章領域への回避、重なり許可切替、保存・再読み込み後の位置一致、390px幅の自然な読み順と横はみ出しなしを確認。検証用の記事変更は復元。109テスト通過。

## リロード時の改ページ判定

写真寸法のResizeObserver反映と文章回避の再計算が終わる前に、続きページへの分割を判定しない。フォント読み込み後、紙面・写真・文章枠の座標、寸法、スクロール寸法が連続3フレーム変わらなくなってから判定する（最大120フレーム）。測定幅も外側コンテナではなく、実際の見開き枠の内幅から求める。実際にあふれる内容の続きページ化は維持する。

検証：1440×900でタイ記事6ページの編集画面・通常表示・再読み込み後の要素座標と寸法が一致。7〜8ページの再読み込み一致、1280×800でも対象見開きの一致を確認。記事データの変更なし。111テスト、型検査、変更コードのLint通過。


行単位回り込みの検証：写真2の自由移動に追従し、写真の下で文章幅が戻ることをブラウザで確認。1440×900で通常表示と編集表示の枠座標が一致。検証用の写真移動は保存せず破棄し、記事データは維持。

## 写真の円形・角丸

直接編集で写真を選び、「写真の形」から四角・円形・角丸を選択する。角丸は0〜100px（初期16px）で調整する。`frames[].shape` と `cornerRadius` に保存し、未指定の既存写真は四角のまま。円形は表示比率を1:1としてcoverで切り抜き、焦点・ズームを利用する。元の比率設定は保持し、四角・角丸に戻すと復元する。キャプションと操作ハンドルは切り抜きの外に残す。文章の回り込みは既存の写真枠を基準にし、円周に沿わせる設定は含まない。

## はみ出しが残る配置の保存

はみ出しは保存を禁止する条件にせず、ページ番号付きの警告として扱う。現在のページや以前に開いた別ページに問題があっても、編集中の配置を保存して後から修正できる。保存中・未変更・比較／スマホプレビュー中の制限、サーバー側のデータ検証、競合検出は維持する。本文を削除したり、はみ出しを隠して解決しない。
